# Roadmap

Every OpenSpec change in this repo, grouped by lifecycle state. This is a living document, not the static version-phase plan in `documentation.md` §134-139 — for the fixed v0.1–v1.0 feature scope, see that doc instead.

## Maintenance convention

This file is maintained **manually**, updated as part of running the OpenSpec workflow — not generated by a script (no build tooling exists yet to host one; see `bootstrap-monorepo-scaffolding/design.md` Decision 4).

- **Planned items** are not yet real OpenSpec changes — no `openspec/changes/<name>/` directory exists for them yet. They're a backlog, ordered by dependency.
- **`/opsx:propose`** → pick the next item from **Planned**, remove it from that list, and add it under **Proposed**.
- **`/opsx:apply`** → once a change's planning artifacts are complete and at least one task is checked, move it from **Proposed** to **Doing**. Once every task is checked, move it to **Done**.
- **`/opsx:archive`** → move the change from **Done** to **Archived**, and repoint its link at the archived location.

A change should appear in exactly one section at a time (Planned items are not "changes" yet, so they don't count against this). Treat a stale entry (wrong section, dead link) as a defect to fix, not a cosmetic issue.

## Done

- [dead-letter-queue-and-replay](openspec/changes/dead-letter-queue-and-replay/proposal.md) — durable dead-letter publication, explicit initial/manual Delivery Runs, workspace-scoped DLQ visibility, and auditable single-delivery/event replay under the same logical Delivery.
- [delivery-attempts-and-retries](openspec/changes/delivery-attempts-and-retries/proposal.md) — immutable delivery-attempt history, five-attempt staged Kafka retry schedule, retry-safe state transitions, attempt-history API, and dashboard visibility; completed by the durable DLQ and replay workflow above.
- [bootstrap-monorepo-scaffolding](openspec/changes/bootstrap-monorepo-scaffolding/proposal.md) — monorepo skeleton, docker-compose infra, `LLM_CONTEXT.md`, and this roadmap itself.
- [auth-minimal](openspec/changes/auth-minimal/proposal.md) — register/login/refresh/logout/me, one workspace per user, refresh-token rotation with reuse detection. First real code in `apps/backend`.
- [project-and-api-key-minimal](openspec/changes/project-and-api-key-minimal/proposal.md) — projects and API keys scoped to the caller's workspace; extracted a shared crypto-hashing util and a standalone `workspaces` module out of `auth`.
- [endpoint-and-subscription-minimal](openspec/changes/endpoint-and-subscription-minimal/proposal.md) — webhook endpoints and event-pattern subscriptions scoped to the caller's workspace; literal-hostname blocklist on URLs, wildcard matcher deferred to routing.
- [event-ingestion-kafka-pipeline](openspec/changes/event-ingestion-kafka-pipeline/proposal.md) — `POST /events` → Postgres → Kafka producer → routing consumer → delivery record → delivery consumer → webhook POST → SUCCEEDED/FAILED (no retries, no signing yet). First real code in `apps/delivery-worker` and `packages/kafka-contracts`; `docker-compose.yml`'s Kafka listener and single-broker `__consumer_offsets` config fixed along the way.
- [basic-dashboard](openspec/changes/basic-dashboard/proposal.md) — first real frontend code (`apps/frontend`): login, project selection, events/deliveries dashboard, endpoint/subscription management UI. Retrofitted pagination (offset/limit) and filtering onto every backend list endpoint, including the four already-shipped ones. Added CORS to `apps/backend` (never needed before a browser called it) — found only by driving the app in a real headless browser, not curl.
