# Endpoint test deliveries

Endpoint tests let dashboard users verify one webhook destination without waiting for a real application event.

`POST /api/v1/endpoints/:id/test` creates a synthetic Event and one Delivery targeted only at the selected Endpoint. It does not evaluate subscriptions and it does not fan out to other Endpoints in the project. Disabled Endpoints reject the test before any Event or Delivery is created.

## Synthetic event shape

Endpoint-test Events use the reserved event type:

```text
relayforge.endpoint.test
```

The payload is generated by RelayForge and is intentionally small:

```json
{
  "message": "RelayForge endpoint test delivery",
  "endpointId": "<endpoint-id>",
  "sentAt": "2026-08-29T10:00:00.000Z"
}
```

The payload never includes API keys, signing secrets, encrypted signing material, arbitrary dashboard input, or endpoint credentials.

## Delivery behavior

Endpoint tests use the same asynchronous delivery path as normal webhook traffic:

- The API returns `202 Accepted` after the test lifecycle is persisted and the first delivery job is published.
- The delivery worker sends the normal webhook body and headers, including `X-RelayForge-Event`, `X-RelayForge-Event-Id`, `X-RelayForge-Delivery-Id`, `X-RelayForge-Timestamp`, and `X-RelayForge-Signature` when the Endpoint is signing-capable.
- Attempts, retries, run history, and dead-lettering follow the same rules as customer-originated deliveries.
- Event, Delivery, and DLQ responses mark endpoint-test traffic so the dashboard can visually distinguish it from customer-originated Events.
